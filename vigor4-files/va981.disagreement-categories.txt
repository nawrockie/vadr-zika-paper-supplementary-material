   These are genuine annotation-scope differences, NOT errors in either tool

5. NEW CATEGORY (not present in the 848-seq comparison) — VIGOR4 PSEUDOGENE
   REFUSAL (VADR-only, additional, PRODUCT-MISSING-2 remainder): 5 x 12 = 60
   5 of the 133 newly-added sequences (MW143017.1, MW143018.1, MW143019.1,
   MW143020.1, MW143021.1) get ZERO VIGOR4 features at all — VIGOR4's log
   states explicitly: "No gene models found. Currently Vigor4 does not
   support annotating Pseudogenes" / "No gene models generated for sequence
   <acc>". VADR, by contrast, still calls all 12 CDS/mat_peptide features for
   these sequences (with FAIL-level alerts: cdsstopn/cdsstopp — in-frame stop
   codons — plus the peptrans cascade), giving VADR full coordinate output
   where VIGOR4 provides none.
   Total: 4 core-scope products x 981 seqs would be 3924, but VIGOR4 only
   attempts 976/981 seqs, so:
     PRODUCT-MISSING-2 total = 2943 (item 4, all 981 seqs x 3 scope-only
       products) + 60 (item 5, 5 seqs x 12 products VIGOR4 skipped
       entirely) = 3003, matching va981.headline.txt exactly.
   This is a genuine VIGOR4 tool limitation (declines to annotate CDSs with
   internal in-frame stops as pseudogenes) rather than a VADR error — but
   it is a real difference in annotation completeness that did not exist
   in the 848-seq (0-ambiguous-nt) comparison, since none of those 848
   sequences carried in-frame stop codons.

6. START/STOP/FRAMESHIFT handling: no coords disagreements traced to this
   among the 976 sequences with shared features. VADR's fails (21/981, see
   va981.added-value-panel.txt) still produce coordinates that MATCH VIGOR's
   where features are shared by both tools.
